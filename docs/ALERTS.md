# การแจ้งเตือน (Alerts)

ระบบประเมินสถานการณ์ของ "สถานที่ที่ติดตาม" (place) ทุกครั้งที่ดึงข้อมูลเสร็จ (ค่าเริ่มต้นทุก 10 นาที)
แล้วส่งข้อความ **เฉพาะเมื่อสถานการณ์เปลี่ยน** — โค้ดอยู่ที่ `src/lib/engine/alerts.ts` (pure function, มี test ครบ)

## ระดับสถานการณ์

| ระดับ | ระยะห่างตลิ่ง (ค่าเริ่มต้น) | ฝนสะสม 24 ชม. | น้ำบนถนน |
|---|---|---|---|
| ปกติ | ≥ 0.60 ม. | < 35.1 มม. | < 5 ซม. |
| เฝ้าระวัง | < 0.60 ม. | ≥ 35.1 มม. (ฝนหนัก) | ≥ 5 ซม. |
| เตือนภัย | < 0.30 ม. | ≥ 90.1 มม. (ฝนหนักมาก) | ≥ 15 ซม. |
| วิกฤต | < 0.10 ม. หรือน้ำล้นตลิ่ง | ≥ 150 มม. | ≥ 30 ซม. |

ผู้ใช้ปรับเกณฑ์ระยะห่างตลิ่ง เกณฑ์ฝน และ "ระดับขั้นต่ำที่ต้องการรับแจ้ง" (เฝ้าระวัง / เตือนภัย / วิกฤต) ได้ในหน้า **แจ้งเตือน**

ระยะห่างตลิ่ง = ความสูงตลิ่งฝั่งที่ต่ำกว่า − ระดับน้ำ (ทั้งคู่เป็น ม.รทก.) ไม่ใช้เกณฑ์ "เตือนภัย/วิกฤต" ของ กทม. ตัดสิน
เพราะหลายจุดเป็นระดับควบคุมการระบายน้ำที่ต่ำกว่าตลิ่งมาก (เช่น วันที่ 28 ก.ย. 2569 กทม. ติดป้ายวิกฤต 97 จาก 312 จุด)

## กติกาการแจ้ง

1. **ยกระดับ** — จุดวัดใดขึ้นไปถึงระดับที่ผู้ใช้เลือก (หรือสูงกว่า) แจ้งทันที รวมถึงครั้งแรกที่สร้างการติดตามแล้วพบว่าอยู่ในระดับนั้นอยู่แล้ว
2. **คลี่คลาย** — ลดระดับเมื่อระยะห่างตลิ่งกลับมาเกินเกณฑ์ **+5 ซม.** (hysteresis กันการแจ้งสลับไปมา) แจ้งเฉพาะเมื่อก่อนหน้านั้นเคยถึงระดับที่ผู้ใช้เลือก
3. **ย้ำเตือนวิกฤต** — ถ้ายังวิกฤตอยู่ แจ้งซ้ำทุก 3 ชั่วโมง
4. **น้ำขึ้นเร็ว** — ระดับน้ำขึ้น ≥ 10 ซม./ชม. (ปรับได้) และอยู่ระดับเฝ้าระวังแล้ว หรือคาดว่าจะถึงเฝ้าระวังภายใน 3 ชม. (คำนวณจากอัตราขึ้นปัจจุบัน)
   แจ้งซ้ำที่จุดเดิมได้ทุก 2 ชม.
5. **ฝน** — ฝนสะสม 24 ชม. สูงสุดใน 3 สถานีใกล้บ้าน (รัศมีไม่เกิน 15 กม.) ข้ามเกณฑ์ขึ้นไป (ลดระดับเมื่อต่ำกว่าเกณฑ์ 5 มม.)
6. **น้ำท่วมถนน** — เซนเซอร์ในรัศมีที่ตั้งไว้รายงานน้ำบนผิวถนนข้ามเกณฑ์ (ลดระดับเมื่อต่ำกว่าเกณฑ์ 3 ซม.)
7. **ข้อมูลค้าง/ขัดข้อง** ไม่ทำให้เกิดการแจ้งเตือน และไม่ลบสถานะเดิม — เมื่อเซนเซอร์กลับมา ระบบเทียบกับสถานะล่าสุดก่อนขาดหาย
8. **ตลิ่งไม่แน่นอน** (ข้อมูลตลิ่งของหน่วยงานผิดปกติ) ยกระดับได้ไม่เกิน "เฝ้าระวัง"
9. ทุกเหตุการณ์ในรอบเดียวกันของสถานที่เดียวกัน **รวมเป็นข้อความเดียว** (หัวข้อเป็นเรื่องที่รุนแรงที่สุด + "อีก N รายการ")

ตัวอย่างข้อความ:

```
เตือนภัย: ประเวศฯ วัดกระทุ่มฯ ห่างตลิ่ง 0.22 ม. (+อีก 1 รายการ)
• เฝ้าระวัง → เตือนภัย · ปตร. คลองประเวศบุรีรมย์ ตอนวัดกระทุ่มเสือปลา: น้ำ 0.83 ม. ตลิ่ง 1.05 ม. ห่างตลิ่ง 0.22 ม. ขึ้น 6 ซม./ชม.
• ฝนสะสม 24 ชม. 72.7 มม. (ฝนหนัก) ที่ สนข.ประเวศ (450 ม.)

พื้นที่: บ้าน
เวลา 03/10 08:35 น.
https://your-host/?place=…
```

## ช่องทางแจ้งเตือน

| ช่องทาง | ผู้ดูแลระบบต้องตั้งค่า | ผู้ใช้ต้องทำ |
|---|---|---|
| Web Push (แจ้งเตือนบนเบราว์เซอร์/มือถือ) | `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (สร้างด้วย `npm run vapid`) | กดอนุญาตการแจ้งเตือน (iPhone/iPad: ต้อง "เพิ่มลงหน้าจอโฮม" ก่อน, iOS 16.4+) |
| LINE (Messaging API) | สร้าง LINE Official Account + Messaging API channel, ใส่ `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_CHANNEL_SECRET`, `LINE_ADD_FRIEND_URL`, ตั้ง webhook เป็น `https://<host>/api/line/webhook` | เพิ่มเพื่อน แล้วพิมพ์รหัส 6 ตัวที่ได้จากหน้าเว็บ |
| Telegram | สร้างบอทกับ @BotFather, ใส่ `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_WEBHOOK_SECRET`, ตั้ง webhook | กดลิงก์ `t.me/<bot>?start=<รหัส>` |
| ntfy | ไม่ต้อง (ค่าเริ่มต้น `https://ntfy.sh`) | ติดตั้งแอป ntfy แล้ว subscribe หัวข้อที่ตั้งชื่อเดายาก |
| อีเมล | `RESEND_API_KEY`, `EMAIL_FROM` (โดเมนที่ยืนยันกับ Resend แล้ว) | กดลิงก์ยืนยันในอีเมล |
| Discord | ไม่ต้อง | วาง Webhook URL ของห้องแชต |

> LINE Notify ปิดบริการแล้ว (31 มี.ค. 2568) จึงใช้ LINE Messaging API แทน — ข้อความ push มีโควตาต่อเดือนตามแพ็กเกจของ Official Account

## การจัดการโดยไม่ต้องสมัครสมาชิก

เมื่อสร้างการติดตาม ระบบให้ **manage token** แบบสุ่ม 256 บิต (เก็บเฉพาะค่า hash ในฐานข้อมูล) และบันทึกไว้ในเบราว์เซอร์
ผู้ใช้ควรเก็บ "ลิงก์จัดการ" ไว้เพื่อแก้ไข/ลบจากอุปกรณ์อื่น — ใครมีลิงก์นี้สามารถแก้ไขการติดตามนั้นได้
